# 2026-10-02

## gomd — 纯 Go Win32 Markdown 浏览器

沙箱之前只验证了"能编译/进程存活"，没真跑，掩盖了运行期 bug。今天通过实测 + 用户真机反馈全部定位并修复。

### 启动崩溃（实测发现）
- `TB_ADDSTRINGW` 错用 ANSI 版常量 `WM_USER+37`，应改 Unicode 版 `WM_USER+38`；否则 `TB_ADDSTRINGW` 返回野值 → `TB_ADDBUTTONSW` 越界 → 0xC0000005。
- 工具栏字符串池不能用 `windows.UTF16PtrFromString`（遇内嵌 NUL 返回 nil），改为手动构造 UTF-16（NUL 分隔+双 NUL 结尾）的 `toolbarStringPool()`。
- `FillRect` 属 user32.dll（非 gdi32），挂错 DLL 导致 panic（`Failed to find FillRect procedure in gdi32.dll`）。

### 主界面"无响应"（用户真机反馈）
- 根因：Go 调度器把跑消息循环的 main goroutine 迁移到别的 OS 线程；Win32 把窗口消息投递到"创建窗口的线程"，`GetMessage` 收不到 → 卡死。沙箱无真实窗口消息故未暴露。
- 修复：`main()` 开头 `runtime.LockOSThread()`。

### 现代外观（manifest）
- 新增 `gomd.manifest`（ComCtl32 v6 视觉样式 + Win10/11 兼容 + PerMonitorV2 DPI 感知）与 `gomd.rc`。
- 用 `/d/msys64/ucrt64/bin/windres.exe gomd.rc -o gomd.syso` 编译，Go 自动链接进 exe。
- 构建：`go build -trimpath -ldflags="-s -w -H windowsgui" -o gomd.exe .`

### 验证
- 单测 `TestRenderSample` / `TestRenderPaint` / `TestToolbarCreate` 全 PASS（含真实 GDI 绘制链路）。
- GUI 版冒烟：进程存活、启动未崩溃。

### 待办（用户决定）
- 真机复验界面响应性 + 现代外观。
- 用户要求"先不 UPX"；网络恢复后可补 `--best --lzma`（预期 2.9MB→~900KB）。

## 晚间补充：用户贴截图"自己看看"，离屏复现后连修 4 个渲染层 bug

用户贴出真机截图（存为 1.PNG）发现叠影/乱码。新增**离屏渲染自检**（render_dump_test.go：CreateDIBSection + paint 落 BMP → python 转 PNG → 自己 Read 看图），复现并修复：

1. **整页文字叠影**（最严重）：`drawUnit` 只存 `item`，paint 误画 `du.item.text`（整段），每个拆分单位都画整段 → `drawUnit` 加 `text` 字段，paint 画 `du.text`。回归断言：排版步进 == measureItem(item, du.text)。
2. **列表列头乱码**：`LVM_INSERTCOLUMNW` 误用 ANSI 值 +27 → 改 **+97**。
3. **工具栏按钮消失**：`TB_ADDBUTTONSW` 误用 ANSI 值 +20 → 改 **+68**。
4. **滚动条不滚动**（代码评审发现）：`handleVScroll` 算出 `pos` 被 `_ = pos` 丢弃 → 改 `setScrollPos2(pos)`；另在 `updateScrollRange` 补 `clampScroll()` 防缩放后越界空白。

判定技巧：列头乱码"中英混合字符"（T锥/9e）= UTF-16 被 ANSI 解码的特征；状态栏中文正常（SB_SETTEXTW=+11 对）说明是"个别常量 A/W 混用"而非全局问题。全部单测 PASS，GUI 冒烟存活，两版 exe 已重建。

## 深夜：用户反馈"字间距有点大，然后表格都没显示"

### 1. 表格完全不显示
- 根因：`buildBlocks` 的 switch 没处理 `*extast.Table`/TableHeader/TableRow/TableCell，落入 `default` 只递归、`collectInline` 永不调用 → 表格零内容。
- 实现：`Block.table *TableData` + `tableCell/tableRow` 模型；`buildTable` 解析；`doTable` 布局（列宽自适应：先量各列自然宽度，超出可用宽度按比例压缩，最小 40px）；`paint` 画表头浅灰底 + 网格（列分隔/行边界/表头下方深色线）+ 列对齐。
- **踩坑**：goldmark `NewTableHeader` 把表头单元格直接挂到 TableHeader 下（**无 TableRow 包装层**），最初按"内含 TableRow"写 → 表头行丢失、rows=2。已改为兼容两种形状。
- 多行单元格：每格单独 `wrapUnits` 到列内容宽度，行高取最大；居中/右对齐按**每个视觉行**实测宽度做偏移，并用 `y→off` 映射同步修正 `linkRect.x`（只作用于当前单元格新增的 linkRect，避免跨格串扰）。

### 2. 字间距偏大
- 根因：逐字/逐单位单独 `TextOut` → 丢 GDI kerning，且每单位单独 `GetTextExtentPoint32` 取整累加产生漂移。
- 修复：新增 `sameItem()`，`wrapUnits`/`doCode` 把相邻同样式单元**合并成一个 drawUnit**（text 拼接），整段一次 TextOut，间距恢复字体本征值。
